# War Dogs 射表计算器

Windows 游戏坐标 OCR 与射表计算工具。方位角以正北（Y 轴正向）为 `0°`，顺时针一周；距离按 `1 游戏单位 = 100 m` 显示。

当前版本：`1.3.0`

## 功能

- RapidOCR CPU 识别为首选，Windows 系统 OCR 作为低内存备用
- 使用少量基色、自然分层与统一自绘标题栏的新界面
- 四个可配置全局热键：设置区域、基准点、目标点和快速目标
- 全局热键使用非独占监听，可与其他程序的相同热键同时生效
- 自动判断框选区域所在的显示器，并按显示器保存默认 OCR 区域
- 从队友发送的聊天消息中临时框选坐标并立即计算，不覆盖默认区域
- 支持手动输入坐标和自定义坐标正则
- 以大字号显示射程、方位角及八方向标记
- 迫击炮与 SPH-2 两发校准模式一键切换
- SPH-2 根据两发计划瞄准点和实际落点反算炮车平台姿态，同时给出低射、高抛修正射表
- 可选等高假设，或加载独立地图高度包计算炮位与目标高差
- 可切换到简洁的置顶结果卡片；拖动边缘调整大小，文字同步缩放
- 每次运行生成一份本地诊断日志，帮助排查全局热键、截图和 OCR 问题
- 截图或 OCR 失败时用红色窗口边框提示

## 使用

运行环境为 Windows 10 1809+ 或 Windows 11 x64，并需要 Microsoft Visual C++ 2015–2022 Redistributable (x64)。解压发布包后运行 `WarDogsDistanceCalculator.exe`。

首次运行先按 `F8` 框选游戏聊天框里的坐标区域。区域会保存到本地配置，下次启动时自动恢复；如果对应显示器已断开或分辨率改变导致原区域失效，程序会要求重新框选。

默认热键：

1. `F8`：设置默认 OCR 区域。
2. `F9`：从默认区域识别并设置基准点。
3. `F10`：从默认区域识别目标点并立即计算。
4. `F11`：临时框选队友分享的坐标，立即识别并计算；不改变默认区域。

热键不会独占 Windows 组合键。如果游戏或其他软件也使用相同热键，按下时双方会
同时响应。程序会忽略按住产生的重复事件，松开后再次按下才会重新触发。

程序目录中的 `WarDogsDistanceCalculator.log` 只保存本次运行的诊断信息。每次启动都会先清空旧内容，不会持续追加或无限增大。如果遇到游戏内热键不响应，请在关闭程序后、再次启动前保留或发送该文件；日志包含收到的功能键或媒体键键码、热键匹配结果、窗口前后台状态、截图及 OCR 结果，不包含截图图像。

主界面支持手动输入 `x12.34, y56.78` 或 `12.34 56.78`。热键、OCR 引擎和坐标正则可在设置窗口修改。

点击主界面右上角的图钉进入置顶模式。置顶小窗只显示射程和方位：

- 按住小窗内部拖动；按住边缘或四角调整大小。
- 双击小窗返回完整界面。
- 右键打开卡片侧边控制菜单：锁形图标用于固定或解除固定，滑条用于调整卡片和菜单的透明度（最低 `35%`）。
- 固定后，左键拖动、缩放和双击返回都会失效，误点也不会抢走游戏焦点；仍可右键解除固定。
- 全局热键在置顶模式下仍然有效。
- 截图或 OCR 失败时边框变红；再次开始识别或识别成功后自动清除。

右上角的武器按钮切换迫击炮与 `SPH-2`。SPH-2 在固定炮位上按以下步骤校准：

1. 设置第一个计划瞄准点并射击；保持对应的低射或高抛按钮状态一致。
2. 用 `OCR 录入下一发` 识别实际落点，或在实际落点输入框填写坐标后点击 `手动录入下一发`。
3. 更换方位并重复第二发。两发计划方位角夹角应在 `30°～150°`。
4. 校准成功后，目标变化会立即给出修正后的射程、地图绝对方位和分划。炮车移动或车身姿态改变后点击 `清除校准` 并重新校射。

超出射表范围时仍会显示目标距离和方位。某一种弹道仍有可用分划时，结果保持可用状态；两种弹道都不可用时才以红框提示失败。

## 地图高度包

高度数据与主程序分开分发。把下载的 `.wdt` 文件放入程序旁的 `terrain-packs` 目录，重新启动后，只有通过 SHA-256 校验且地图标识正确的数据包才会出现在高度模型选项中。当前识别以下文件：

高度数据来源于 Apollyon 维护的开源社区项目 [WARDOGS Artillery Calculator](https://github.com/apollyon-sys/wardogs-calculator) 所发布的 [Terrain3D 数据](https://assets.wardogs-artillery.com/releases/assets-v1/data/terrain/)。本项目记录上游 manifest 的 SHA-256，并按 manifest 中的 SHA-256 校验每个源区块，再将网格重新量化、压缩为 `.wdt`；没有重新解包游戏地图。详细来源、处理方式和权利说明见 [TERRAIN_DATA_NOTICE.md](TERRAIN_DATA_NOTICE.md)。单独分发高度包时应同时附带该声明文件。

| 地图 | 文件名 | SHA-256 |
| --- | --- | --- |
| Bakurani | `bakurani.wdt` | `9c79af2f69df5023f6e2e944329ae80981432e7115832ae801da067bd79bfdde` |
| Ozeti | `ozeti.wdt` | `f636225e89ffe19111da58466d4db60e4ccff285c3cfa11d8c30b959f544c400` |
| Zestafona | `zestafona.wdt` | `e60f95a6e23791164342fe51b465ac04238f338f1f4293aef664b61513ecc048` |

数据以 `2 m` 水平间隔、`0.1 m` 高程单位量化，按区块使用 Zstandard 压缩。程序只在查询坐标时解压所需区块，并使用小型 LRU 缓存；切换地图时只打开当前地图，不会把整张地图读入内存。

## 使用限制

- 截图使用 Win32 GDI `BitBlt`。Windows 11 x64 本机已验证窗口化、无边框全屏和游戏全屏模式能够捕获；其他游戏的独占全屏或反捕获机制可能返回黑图。
- 置顶小窗适用于窗口化和无边框全屏。真正的独占全屏可能绕过桌面合成并覆盖普通 Windows 顶层窗口，此时请将游戏改为无边框全屏。
- 本程序不注入或挂钩游戏进程，不读取游戏内存，也不模拟游戏操作，只执行屏幕截图、OCR 和坐标计算。不同游戏及服务器规则不同，请自行确认是否允许使用第三方辅助工具。

## 构建

构建需要 Visual Studio 2022 的 C++ 桌面工作负载及 Qt 6.8 MSVC 2022 x64。脚本默认从 `D:\Qt\6.8.3\msvc2022_64` 读取 Qt，也可通过 `QT_ROOT` 指定其他位置。在 PowerShell 中进入项目目录并执行：

```powershell
.\build.ps1 -Configuration Release -Package
```

脚本会配置 Release 构建、运行测试、部署 Qt 运行库并生成：

```text
out\WarDogsDistanceCalculator-v1.3.0-win-x64.zip
```

仓库已携带 ONNX Runtime x64 运行文件和 PP-OCRv6 识别模型，构建过程不联网。

## 目录

- `src/`：Qt Widgets UI、Win32 热键与截图、OCR、车辆弹道和地形包实现
- `include/wardogs/`：模块接口
- `tests/`：纯计算、正则解析、CTC 解码和真实截图测试
- `tools/`：OCR 性能与 Windows OCR 诊断工具
- `assets/models/`：识别模型
