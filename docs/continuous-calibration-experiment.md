# 持续校准模型实验草案

状态：讨论稿，仅用于 `codex/continuous-calibration-experiment`，不改变发布版行为。

## 现有基线

当前 SPH-2 用两发的计划瞄准点、实际落点和弹道分支，反算一个固定的三维炮台旋转。两发的夹角残差描述这两组方向无法被同一个刚体旋转完全解释的程度。它既不是落点误差，也不能保证第三发命中。高度模式进一步依赖地形高度和等效平地射程近似。

Python 数学核心已有相同的两发旋转与高度计算，但 Python 应用的 UI、置顶卡片、热键等仍落后于 C++ v1.3.1，且其工作区有尚未提交的地形和 UI 改动。本实验先在 C++ 分支保持一个唯一的应用基线，不为数学试验同步两套 UI。若需要拟合或绘图，可使用独立 Python 分析脚本读取同一批样本，而不是修改旧版 Python 应用。

## 每发必须记录什么

最少需要炮位坐标、目标坐标、实际使用的弹道分支、**实际发射时的方位角与分划**、实际落点坐标，以及使用的高度模型。用户选择射表后，程序应冻结那一发显示的射击参数；目标或校准状态后来变化，不应改写历史记录。只有目标与落点而没有实际使用的射击参数，无法可靠区分射手操作偏差、旧模型补偿和弹道模型误差。

换炮位、车体转向或换高度模型时开始新的校准会话。录错的一发应可删除，历史样本不应静默覆盖。原先两发计划瞄准点可作为最初两发的射击参数来源，但后续发射应记录真实采用的参数。

## 分阶段模型

1. **基线**：保持当前两发解。留出后续样本做回放验证，不用参与拟合。
2. **多发刚体旋转**：以每发实际射击方向和由落点反推的世界方向为观测，用加权最小二乘估计同一个旋转。检查观测方向是否足够分散；近乎同方向的多发不能假装提供了完整姿态信息。
3. **抗异常值**：坐标 OCR 错误、弹道分支选错、射手没有使用显示的分划等，应显示为大残差并允许排除。稳健权重不能悄悄删除样本。
4. **分离弹道系统误差**：如果残差随距离、高差或高低弹道有稳定趋势，再考虑各弹道的低维距离修正。样本不足时只更新旋转，避免用高阶曲线把随机散布拟合成“精度”。

“持续”意味着新样本加入后重新估计并显示样本数、误差与可用范围，不意味着永远只拿最近两发重算。可评估适度降低旧样本权重，但必须先证实车体姿态随时间缓慢漂移；实际移动炮车时应重置会话。

## 如何判定是否值得继续

用按时间顺序的下一发预测，而不是训练样本上的拟合残差，比较现有两发模型与候选模型的落点误差（米）的中位数、90 分位数及方向/距离分量。分别统计高低弹道、远近射程、平地/地图高度模式。若提升只出现在训练数据，或牺牲某一弹道的稳定性，则不加入 UI。

最终可达到的精度还会受到游戏散布、坐标显示精度、射手执行误差、射表插值和地形模型误差限制；在没有实测样本前，不承诺“指哪打哪”。
