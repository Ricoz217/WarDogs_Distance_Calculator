# 持续校准模型实验草案

状态：讨论稿，仅用于 `codex/continuous-calibration-experiment`，不改变发布版行为。

## 现有基线

当前 SPH-2 用两发的计划瞄准点、实际落点和弹道分支，反算一个固定的三维炮台旋转。两发的夹角残差描述这两组方向无法被同一个刚体旋转完全解释的程度。它既不是落点误差，也不能保证第三发命中。高度模式进一步依赖地形高度和等效平地射程近似。

Python 数学核心已有相同的两发旋转与高度计算，但 Python 应用的 UI、置顶卡片、热键等仍落后于 C++ v1.3.1，且其工作区有尚未提交的地形和 UI 改动。本实验先在 C++ 分支保持一个唯一的应用基线，不为数学试验同步两套 UI。若需要拟合或绘图，可使用独立 Python 分析脚本读取同一批样本，而不是修改旧版 Python 应用。

## 每发必须记录什么

最少需要炮位坐标、目标坐标、实际使用的弹道分支、**实际发射时的方位角与分划**、实际落点坐标，以及使用的高度模型。用户选择射表后，程序应冻结那一发显示的射击参数；目标或校准状态后来变化，不应改写历史记录。只有目标与落点而没有实际使用的射击参数，无法可靠区分射手操作偏差、旧模型补偿和弹道模型误差。

换炮位、车体转向或换高度模型时开始新的校准会话。录错的一发应可删除，历史样本不应静默覆盖。原先两发计划瞄准点可作为最初两发的射击参数来源，但后续发射应记录真实采用的参数。

## 两层模型与可辨识性

1. **基础层固定**：仍用夹角接近 90° 的最初两发建立三维平台旋转 `R₀`。只要炮车位置、车身姿态及高度模型没变，后续射击不直接重估 `R₀`。两发夹角残差只衡量这两组方向的内部一致性，不能当作命中精度。
2. **目标附近的局部层**：同一目标接连开火时，后续方向几乎相同。这批样本无法重新辨认三维旋转，但可以估计这一目标、这一弹道附近的二维局部偏差（左右和远近，或等价的方位与分划修正）。给它一个以零为中心的先验，避免少数噪声样本造成大幅修正。
3. **分组隔离**：每个炮位会话内，按目标与实际使用的高低弹道分组；高度模型也属于会话条件。转向新目标时先使用基础层 `R₀`，**绝不直接套用旧目标组的局部修正**。即使方位相近，射程或高差不同也不能仅凭方位角合并样本。
4. **以后才考虑跨组学习**：只有多个不同方位、射程的组都显示相同趋势，且留出整个目标组做验证仍能提高命中精度，才尝试非常受限的全局修正。每组先汇总为一条证据，不能让某个目标的二十发压倒其他目标或基础两发。

局部模型可以先使用基础模型的前向预测 `F₀(实际方位, 实际分划)`，比较实际落点与预测落点。在当前目标附近用局部响应矩阵把落点偏差换成射击参数修正，并加入正则化、单发影响上限和总修正上限。最大射程附近距离对分划可能不敏感，矩阵会病态；此时必须降低可信度或拒绝距离方向的更新，不能硬求逆。

后续落点的可靠性低于基础两发。单发大偏差可能是真实系统误差，也可能是手动输入、OCR、弹道选择或游戏散布。第一阶段比较“至少两到三发相互一致才启用补偿”与“每发小步更新”两种策略；稳健估计与异常值提示都保留原始样本，允许用户纠错，而不是悄悄删除。

“持续”表示同一目标的新样本使该组估计逐渐稳定，不表示永远只拿最近两发重算。换炮位或车身姿态改变后全部重置；只换目标则保留基础层并开始另一局部组。

## 如何判定是否值得继续

用按时间顺序的下一发预测，而不是训练样本上的拟合残差，比较现有两发模型与候选模型的落点误差（米）的中位数、90 分位数及左右/远近分量。分别统计各目标组的第 1 发与后续发、高低弹道、远近射程、平地/地图高度模式。**新目标的第一发不得因为旧组补偿而明显变差。**若提升只出现在训练数据，或牺牲某一弹道、另一目标组的稳定性，则不加入 UI。

最终可达到的精度还会受到游戏散布、坐标显示精度、射手执行误差、射表插值和地形模型误差限制；在没有实测样本前，不承诺“指哪打哪”。
