# 持续校准模型实验草案

状态：C++ 实验原型，仅用于 `codex/continuous-calibration-experiment`，不改变发布版行为。

## 现有基线

当前 SPH-2 用两发的计划瞄准点、实际落点和弹道分支，反算一个固定的三维炮台旋转。两发的夹角残差描述这两组方向无法被同一个刚体旋转完全解释的程度。它既不是落点误差，也不能保证第三发命中。高度模式进一步依赖地形高度和等效平地射程近似。

Python 数学核心已有相同的两发旋转与高度计算，但 Python 应用的 UI、置顶卡片、热键等仍落后于 C++ v1.3.1，且其工作区有尚未提交的地形和 UI 改动。本实验先在 C++ 分支保持一个唯一的应用基线，不为数学试验同步两套 UI。若需要拟合或绘图，可使用独立 Python 分析脚本读取同一批样本，而不是修改旧版 Python 应用。

## 用户流程

两发建立基础模型 → 每次输入新落点后更新持续补偿 → 换目标继续使用和更新同一份学习状态 → 玩家认为偏离时点击“清除持续补偿”，立即回到最初的两发基础模型。换目标不是清除或重新校准的触发条件。“持续补偿”是依据全部有效观测重新估计有界修正，不是把每一发算出的偏移量直接相加；直接累加会随噪声漂移。

## 每发必须记录什么

最少需要炮位坐标、目标坐标、选定的弹道分支、**程序当时给出的方位角与分划快照**、实际落点坐标，以及使用的高度模型。如果用户愿意，可另外填写实际操作的设定；不能要求玩家每发都准确照做或如实记录。目标或校准状态后来变化，不应改写历史快照。没有真实操作值时，快照只是带人工误差的代理观测，模型不能可靠区分射手操作偏差与弹道误差，必须按较低可信度处理。

换炮位、车体转向或换高度模型时开始新的校准会话。录错的一发应可删除，历史样本不应静默覆盖。原先两发计划瞄准点可作为最初两发的射击参数来源；后续至少冻结当时显示的参数，而不把它冒充成已经核实的实际操作值。

## 两层模型与可辨识性

1. **基础快照不可变**：仍用夹角接近 90° 的最初两发建立三维平台旋转 `R₀`。后续可以叠加受严格限制的在线全局修正，但始终保留原始 `R₀` 作为先验与一键回退点。两发夹角残差只衡量这两组方向的内部一致性，不能当作命中精度。
2. **目标附近的局部层**：同一目标接连开火时，后续方向几乎相同。这批样本无法重新辨认三维旋转，但可以估计这一目标、这一弹道附近的二维局部偏差（左右和远近，或等价的方位与分划修正）。给它一个以零为中心的先验，避免少数噪声样本造成大幅修正。
3. **跨目标连续使用**：每个炮位会话保留全部有效观测，目标分组只用于衡量支持范围和验证，不是互不相通的模型，更不是可靠性标签。预测新目标时，保留有界的共享修正，并根据方位、射程、高差和弹道分支与历史数据的接近程度，平滑混入局部修正；离已有数据越远，局部修正越趋近零。不能因为方位相近就无视射程和高差，也不能因换了目标就抹掉历史补偿或降低该发数据自身的可信度。
4. **谨慎学习共享修正**：单个方向的连续射击难以区分共享误差和当地误差，因此共享层始终受基础模型约束，更新幅度很小；跨不同方位、射程的证据一致时再提高其可信度。每个目标组先汇总为带不确定度的证据，不能让某个目标的二十发压倒其他目标或基础两发。换目标后立即继续使用当前模型，但缺少支持的修正会自动缩弱，而不是等待跨组验证后才允许任何迁移。

局部模型可以先使用基础模型对当次设定快照的前向预测 `F₀(方位, 分划)`，比较实际落点与预测落点；若用户提供了可信的真实操作值，则替换快照。当前目标附近可用局部响应矩阵把落点偏差换成射击参数修正，并加入正则化、单发影响上限和总修正上限。最大射程附近距离对分划可能不敏感，矩阵会病态；此时必须降低可信度或拒绝距离方向的更新，不能硬求逆。

后续落点有手动射击误差，其大小是连续变化的，不应给所有后续发相同权重。单发大偏差可能是真实系统误差，也可能是手动输入、OCR、弹道选择或游戏散布。不能仅因偏离当前预测很远就判为坏数据：先按当前预测不确定度、邻近观测的一致性和输入可信度确定影响力，并限制单发对输出的最大改变量。孤立的异常发暂时降权；若随后多发在相近条件下呈现一致偏移，应逐步提高该趋势的权重，而不是永远视为离群。第一阶段比较“至少两到三发相互一致才启用较大补偿”与“每发小步更新”两种策略；稳健估计与异常值提示都保留原始样本，允许用户纠错，而不是悄悄删除。

### 观测置信度与补偿适用度

这两个量必须分开：**观测置信度**衡量该发落点是否像一次可信的、带正常操作误差的射击；**补偿适用度**衡量旧样本学到的修正能否迁移到当前射击条件。换目标可能降低旧局部补偿的适用度，但不能直接降低新落点的观测置信度。

对每发先冻结射击前的预测落点 `ŷ`，录入实际落点 `y` 后计算二维残差 `r = y - ŷ`。用操作散布、坐标/OCR 误差与当前位置的模型预测不确定度共同构成 `Σ`，考察标准化残差 `rᵀΣ⁻¹r`，而不是用固定的米数阈值；方向与距离的误差尺度也可能不同。若新目标远离历史数据，模型预测不确定度应增大，因此大的原始残差不自动意味着玩家录错。误差尺度须由实测样本校准，不能先把计算出的数值称为已校准概率。

再检验该发是否能在**有界的小幅模型更新**下被解释，同时不明显损害对先前可靠射击的预测；计算置信度时不能先用该发大幅改写模型、再以改写后的零残差证明它可信。孤立且无法与邻近或后续射击共同解释的落点，给予较低但非零的拟合权重，并保留供后续重新评估；同方向的多发若持续呈现同一种偏差，就构成新规律的证据。即使如此，连续一致的错误操作与真实系统偏差仍可能无法区分，置信度只能表示与模型及噪声假设的相容程度。

### 权重与梯度不是同一件事

- **可靠性权重**表示观测有多可信：基础两发固定为基线，后续人工发射依据观测置信度连续加权；与相近条件下的其他可靠观测及有界模型都不一致的一发由稳健损失进一步降低影响。权重不能把错误操作自动识别为真相，也不应由换目标、射程远近或单次偏差的原始大小直接决定。
- **几何信息**表示一发能区分哪些参数：对模型参数求预测落点的导数（雅可比矩阵）。方向、射程、高差变化会改变它。多个近乎相同的方向即使打得很多，导数提供的信息仍高度重复；适当分散的不同组才可能辨认全局参数。
- 因此不应把“夹角越大”或“梯度模长越大”直接当作单发权重。梯度大也可能让输入误差放大。拟合时用可靠性权重控制噪声，用导数和信息矩阵检查可辨识方向，并对全局变化加回到 `R₀` 的正则化与每次更新上限。

概念上把每发偏差拆为 `基础模型 + 有界在线共享修正 + 随射击条件平滑变化的局部修正 + 噪声`。单一目标下，共享与局部项可能产生几乎一样的落点变化，数学上不能唯一分开；此时主要把证据留在局部层，仅允许保守的共享更新，而不是让优化器凭权重自行决定。这是观测不足，不是更复杂的梯度计算就能解决的问题。

### 回退与会话边界

界面提供“清除持续补偿”：把在线共享修正和全部局部修正置零，立即回到原始两发基础模型 `R₀`。后续样本仍可保留供实验诊断，但从活动拟合集中移除；否则下一次重算又会把清除的补偿带回来。换炮位或车身姿态改变后连基础两发一起重置；只换目标则保留基础快照和完整的持续学习状态，由模型自行调整旧数据在新目标处的影响。

“持续”表示新落点会不断更新同一会话的估计，不表示永远只拿最近两发重算，也不要求玩家为每个目标重新开始。任何自动降权都无法保证识别连续多次相同的错误操作，因此手动清除仍是必要的安全回退。

## 如何判定是否值得继续

用按时间顺序的下一发预测，而不是训练样本上的拟合残差，比较现有两发模型与候选模型的落点误差（米）的中位数、90 分位数及左右/远近分量。分别统计各目标组的第 1 发与后续发、高低弹道、远近射程、平地/地图高度模式，并对整个目标组做留出验证。重点检验换目标后的第一发：旧数据应在相近条件下提供帮助，在条件差异大时避免明显负迁移，同时不得把正常换目标自动标为低可信数据。另用孤立录错、手动操作误差大小不同、连续一致偏移三类样本检验置信度、降权与重新接纳的行为。若提升只出现在训练数据，或牺牲某一弹道、另一目标组的稳定性，则不加入 UI。

最终可达到的精度还会受到游戏散布、坐标显示精度、射手执行误差、射表插值和地形模型误差限制；在没有实测样本前，不承诺“指哪打哪”。

## 第一版可测试原型

实验分支的 C++ 原型把每发冻结的实际方位与分划，与“两发基础模型要命中该实际落点所需的方位与分划”比较，得到该发的方位/分划补偿证据。按弹道分开拟合；同一目标附近的证据用方位、距离和高差平滑加权，远处逐渐回退到有界的跨目标共享补偿。共享层先以每个目标组为单位汇总，再降低与其他组矛盾的组的跨目标影响；该组在自己目标附近仍可形成局部修正。单发补偿的即时影响和总修正幅度都有上限。对缺少相近历史的一发，过大的补偿先给低影响；后来相近射击重复这个偏差时重新计算其一致性并提高影响。

此版相对一致性评分使用方位/分划的固定实验噪声尺度，并非由实测散布校准的概率；不能把 `0.8` 理解为“80% 机会真实”。下一阶段需收集包含正常操作误差、录错和不同目标的实际样本，再估计噪声尺度、检验评分校准程度，并进行按时间顺序的留出评估。当前代码不声称已实现上文概念性的完整预测协方差 `Σ`。

测试时：完成两发校准，选定目标和低射/高抛，在射击前点击“记录当前射击”；若游戏中使用的方位或分划与显示值不同，修改下方实际设定。射后手动或 OCR 录入落点。更换目标后继续重复，不清空历史。若误按记录，可“取消本发”；若感觉持续补偿偏离，可“清除持续补偿”，两发基础模型仍保留。换炮位或高度模型会清除包括两发基础模型在内的当前会话。
